## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Algorithmen, Turingmaschine & die Grenze der Berechenbarkeit
Ein Computer „denkt“ nicht kreativ – er arbeitet stur einen **Algorithmus** ab: eine **eindeutige, endliche Schritt-für-Schritt-Vorschrift**, die für eine Eingabe in endlicher Zeit ein Ergebnis liefert.

Bereits 1936 – noch bevor es elektronische Computer gab – entwarf der Brite **Alan Turing** das berühmte theoretische Gedankenmodell der **Turingmaschine**: Ein unendlich langes Band mit Feldern (Speicher), auf dem ein Lese-/Schreibkopf Zeichen liest, überschreibt und nach einer festen Zustandstabelle nach links oder rechts wandert. So simpel dieses Modell klingt: Nach der **Church-Turing-Hypothese** kann jede Programmiersprache, die **Turing-vollständig** ist (wie Python, Java oder C), jedes überhaupt berechenbare Problem lösen.

Gleichzeitig entdeckte Turing eine harte Grenze: Mit seiner *universellen Turingmaschine* (die Daten **und** Programmcode auf demselben Band speichert) bewies er, dass das **Halteproblem unentscheidbar** ist. Es kann also kein allgemeines Programm geben, das für *jedes* beliebige andere Programm vorhersagt, ob es irgendwann anhält oder in einer Endlosschleife hängen bleibt. *(Turing wurde übrigens auch durch den Turing-Test bekannt, der prüft, ob eine Maschine im Dialog nicht mehr von einem Menschen zu unterscheiden ist.)*

### 2. Das EVA-Prinzip und die Von-Neumann-Architektur
Jede Informationsverarbeitung im Alltag folgt dem **EVA-Prinzip**:
1. **Eingabe (E):** Daten kommen über Tastatur, Maus, Netzwerk oder Sensorik ins System.
2. **Verarbeitung (V):** Der Prozessor rechnet oder entscheidet anhand von Programmbefehlen.
3. **Ausgabe (A):** Das Ergebnis landet auf dem Bildschirm, im Drucker, in einer Datenbank oder als Steuersignal.

Damit man für ein neues Problem nicht jedes Mal Kabel umlöten muss, formulierte **John von Neumann** Mitte der 1940er-Jahre die bis heute gültige Rechnerarchitektur aus **vier Hauptkomponenten**:
- **Rechenwerk (ALU – Arithmetic Logic Unit):** führt Rechenoperationen (`+`, `-`) und logische Vergleiche (`AND`, `OR`, `<`) aus.
- **Steuerwerk (Control Unit):** holt Befehle aus dem Speicher, entschlüsselt sie und gibt dem Rechenwerk und den anderen Teilen den Takt vor.
- **Speicherwerk (RAM):** speichert **Daten UND Programme gemeinsam im selben Arbeitsspeicher**! Genau das war der geniale Durchbruch – ein Programm ist für den Computer einfach eine Folge von Zahlen im Speicher.
- **Ein-/Ausgabeeinheit (E/A / I/O):** verbindet das System über Schnittstellen mit der Außenwelt.

### 3. Worked Example: So arbeitet ein virtueller Prozessor (Registermaschine)
Im Inneren arbeitet das Von-Neumann-Prinzip über **Register** – winzige, extrem schnelle Speicherzellen direkt im Prozessor (z. B. Rechenregister `A`, `B`), ein **Statusregister (`C`)** für Ergebnis-Flags (z. B. *Ergebnis = 0?* oder *Überlauf?*) sowie den **Stack-Pointer (`S`)**, der auf einen Stapelspeicher (*LIFO: Last In, First Out*) zeigt.

> **Worked Example (Zwei Zahlen aus dem RAM addieren):**  
> In RAM-Adresse `$0` liegt die Zahl `5`, in `$1` liegt `7`. Die CPU soll beide addieren und das Ergebnis in `$2` sichern:  
> 1. **`MOV A, $0`** → Kopiert den Inhalt von Speicheradresse `$0` (`5`) in Register `A`.  
> 2. **`ADD A, $1`** → Das Rechenwerk addiert den Inhalt von `$1` (`7`) zu Register `A` → in `A` steht jetzt `12`.  
> 3. **`MOV $2, A`** → Kopiert den Inhalt von Register `A` (`12`) zurück in Speicheradresse `$2`.  
>  
> Jeden dieser Befehle durchläuft die CPU im ewigen **Befehlszyklus**: **Fetch** *(Befehl aus RAM holen)* → **Decode** *(im Steuerwerk entschlüsseln)* → **Execute** *(in ALU/Registern ausführen)*.
