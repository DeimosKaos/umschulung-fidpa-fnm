## Schritt 0 – Priming (Kurzcheck vorab)
CIDR, VLSM und NAT haben die endgültige Erschöpfung von IPv4 nur hinausgezögert. Für Milliarden Smartphones, Server und IoT-Geräte braucht das Internet den 128-Bit-Nachfolger **IPv6** – und clevere Router sowie Hilfsdienste (DHCP, NAT, Proxy), damit Pakete sicher über den Globus finden.

## Schritt 2 – Einmaliges Lesen: Das Phänomen verstehen

### 1. IPv6: 128 Bit, Schreibweise & Header
Um den knappen 32-Bit-IPv4-Adressraum abzulösen, führt **IPv6** (RFC 2460, früher *IPng*) **128-Bit-Adressen** ein (über $3{,}4 \cdot 10^{38}$ Adressen). Man notiert sie als **acht vierstellige Hexadezimalgruppen** mit Doppelpunkten:
- Beispiel: `4A29:30B4:0031:0000:0000:0092:1A3B:3394`
- **Kürzungsregeln:** Führende Nullen innerhalb eines Blocks dürfen entfallen; zusammenhängende reine Nullblöcke dürfen **genau einmal** pro Adresse durch `::` ersetzt werden → `4A29:30B4:31::92:1A3B:3394` (einmalig, damit die Länge eindeutig rekonstruierbar bleibt!).
- **Präfixe (Adresstyp) + Schnittstellen-ID:** `2000::/3` sind global eindeutige Unicast-Adressen (48 Bit externes Routing-Präfix + 16 Bit Site-Topologie + 64 Bit Schnittstellen-ID, oft aus der MAC-Adresse generiert), `FE80::/10` sind Link-Local-Adressen, `FF00::/8` sind Multicast-Adressen.
- **Schlankerer Header:** Der IPv6-Basis-Header ist fest **40 Byte (320 Bit)** lang. Seltene Optionen wandern in **Erweiterungs-Header** (über `Next Header` verkettet, z. B. Routing, Fragmentierung durch den Absender selbst, Authentication, ESP-Verschlüsselung). Das Feld **Hop Limit** ersetzt die IPv4-**TTL** (*Time to Live*: jeder Router zieht 1 ab; bei `0` wird das Paket verworfen), das **Flow Label** markiert Echtzeitströme für Quality of Service (QoS).
- **Übergangsproblem & Lösung:** Da IPv4 und IPv6 inkompatibel sind, nutzt man **IPv6-Tunneling** (über Tunnel-Broker): Ein komplettes IPv6-Datagramm wird als Nutzlast in ein IPv4-Datagramm verpackt und am Ziel wieder ausgepackt.

### 2. IP-Routing: Forwarding, Default-Gateway & Routing-Tabellen
Liegt das Ziel *nicht* im lokalen Subnetz, übernimmt ein **Router**:
- **IP-Forwarding** = bloße Weiterleitung zwischen zwei festen Schnittstellen (z. B. im LAN); **Routing im engeren Sinn** = dynamische Wegwahl unter mehreren Routen nach geringsten „Kosten“ (**Metrik**, meist Hop-Anzahl).
- **Default-Gateway (Standard-Router):** nimmt alle Pakete entgegen, für die der Host keine speziellere Route kennt. *(Begriffsfalle: Im weiteren Sinn heißt „Gateway“ auch ein Verbindungsrechner über alle OSI-Schichten = Application Level Gateway.)*

#### Worked Example: Eine Routing-Tabelle (`netstat -rn`) lesen
Im Entwicklungsnetz `196.87.99.0/24` steht Host `curie` (`196.87.99.8`). Ins Nachbarnetz `196.87.98.0/24` geht es über Router `196.87.99.2`, ins Internet über `196.87.99.1`:
```text
Destination   Gateway       Flags  Interface
127.0.0.1     127.0.0.1     UH     lo0       (H = Host-Route, U = Up)
196.87.99.0   196.87.99.8   U      le0       (lokales Netz direkt über NIC)
196.87.98.0   196.87.99.2   UG     le0       (G = Gateway/Router ins Grafiknetz)
default       196.87.99.1   UG     le0       (Default-Gateway ins Internet)
```
Jeder passierte Router zählt als **Hop** (bei 8-Bit-TTL im IPv4-Header maximal 255 Hops).

### 3. Routing-Protokolle: Interior (AS) vs. Exterior
Zusammenhängende Netze eines Betreibers bilden ein **Autonomes System (AS)**:
- **RIP (Routing Information Protocol):** Interior-Protokoll (Daemon `routed`), tauscht alle 30 Sekunden Tabellen aus, **maximal 15 Hops** (`16` = unerreichbar). Alt-RIP kennt kein CIDR/VLSM (erst `RIP-2`). Um Ausfall-Schleifen zu verhindern, nutzt man **Split Horizon** (gelernte Routen nicht über denselben Weg zurückmelden) bzw. **Poison Reverse** (aktiv Metrik `16` senden).
- **OSPF (Open Shortest Path First):** modernes Interior-Link-State-Protokoll. Jeder Router baut nach **Dijkstras Shortest-Path-First-Algorithmus** einen Netzgraphen auf, prüft Nachbarn per **Hello-Paketen**, verbreitet Änderungen blitzschnell per **LSA-Flooding** (*Link State Advertisements*) und unterteilt große AS in **Areas**.
- **BGP (Border Gateway Protocol):** **Exterior-Routing-Protokoll** zwischen Autonomen Systemen (z. B. Provider am Austauschpunkt **DE-CIX**). BGP-Peers kommunizieren zuverlässig über **TCP-Port 179**, tauschen vollständige Pfadvektoren aus und halten die Verbindung per **KEEPALIVE** aktiv.

### 4. DHCP, NAT / IP-Masquerading (PAT) & Proxyserver
- **DHCP (Dynamic Host Configuration Protocol):** automatisiert die TCP/IP-Vergabe (Erweiterung von BOOTP). Ein startender Client sendet ein **`BOOTREQUEST`**-Broadcast an `255.255.255.255`. Der DHCP-Server vergibt aus einem **DHCP-Pool** eine IP samt Subnetzmaske und Gateway als zeitlich befristete **Lease** (Pacht – so werden Adressen auch bei abgestürzten Clients wieder frei). *Wichtig:* Server mit festen IPs aus dem Pool ausschließen!
- **NAT & IP-Masquerading (PAT):** Da private IPv4-Adressen (`192.168.x.x` etc.) im Internet nicht geroutet werden, übersetzt der Router sie in öffentliche IPs (**NAT**, RFC 3022). Beim **IP-Masquerading / PAT** (*Port Address Translation*) teilen sich *alle* internen Clients **eine einzige öffentliche IP** und werden über ihre **Portnummern** unterschieden. Schöner Nebeneffekt: Interne Rechner sind von außen unsichtbar (zusätzliche Sicherheit; Linux nutzt z. B. Netfilter/`iptables`, Windows bietet *ICS* als einfachere, unsichere Variante).
- **Proxyserver:** Ein **Application Level Gateway** (z. B. **Squid** oder Apache `mod_proxy`), das als Stellvertreter Anfragen für Clients stellt und häufig abgerufene Webseiten im **Cache** zwischenspeichert.
