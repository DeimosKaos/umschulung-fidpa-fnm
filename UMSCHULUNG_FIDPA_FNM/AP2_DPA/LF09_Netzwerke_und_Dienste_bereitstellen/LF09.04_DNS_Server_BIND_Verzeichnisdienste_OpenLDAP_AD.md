## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Der DNS-Server BIND (`named` – Kersken 5.6.4 & 15.1.1)
Das **Domain Name System (DNS)** übersetzt Hostnamen in IP-Adressen (und umgekehrt). Die verbreitetste Open-Source-Implementierung ist **BIND** (Daemon: `named`, Konfigurationsdatei: `/etc/named.conf`; Windows-Gegenstück: Microsoft DNS Server).
- **Zonen-Typen in `named.conf`:**
  - `type master`: Primärer autoritativer Server für eine Zone (z. B. `db.example.com`).
  - `type slave`: Replikat, das Zonendaten vom Master übernimmt (Ausfallsicherheit).
  - `type hint` (`zone "."`): Verweist auf die Root-Nameserver (`named.root`).
  - *Caching-only (`forwarders` + `forward only`):* Speichert nur Antworten vorgelagerter DNS-Server zwischen.
- **Reverse-Lookup-Zone:** Wandelt IP → Hostname über die umgedrehte Adresse unter `.in-addr.arpa` (IPv4) bzw. `.ip6.arpa` (IPv6).

### 2. Die wichtigsten DNS Resource Records (Kersken 15.1.1)
Jede Zonendatei beginnt mit `$TTL` (Cache-Lebensdauer) und einem **`SOA`-Record** (*Start of Authority*: MNAME, RNAME, Seriennummer `JJJJMMDDVV`, Refresh, Retry, Expire, Negative-Caching):
- **`A` / `AAAA`:** Verknüpft Hostname mit **IPv4-** (`A`) bzw. **IPv6-Adresse** (`AAAA`). Mehrere `A`-Records für denselben Namen ermöglichen einfaches *Round-Robin-Load-Balancing*.
- **`PTR` (*Pointer*):** Gegenstück in der Reverse-Zone (IP → Hostname).
- **`CNAME` (*Canonical Name*):** Alias von einem Hostnamen auf einen anderen (darf nicht auf derselben Hierarchiestufe mit einem `A`-Record der Hauptdomain kollidieren!).
- **`NS` (*Nameserver*):** Nennt die autoritativen Nameserver der Zone (oder delegiert Subdomains).
- **`MX` (*Mail Exchange*):** Ziel-Mailserver der Domain inkl. **Priorität** (kleinere Zahl = höhere Priorität, z. B. `0` vor `10`).

### 3. Verzeichnisdienste: OpenLDAP & Active Directory (Kersken 15.1.2)
Verzeichnisdienste sind hierarchische Datenbanken für Benutzer, Gruppen und Geräte. Fast alle modernen Dienste nutzen **LDAP (*Lightweight Directory Access Protocol*)** – z. B. **Microsoft Active Directory (AD)** oder **OpenLDAP** (`slapd`, Konfiguration `/etc/openldap/slapd.conf` bzw. `slapd.d`).
- **DIT (*Directory Information Tree*) & DN:**
  - `dc` (*domain component*): Wurzel (z. B. `dc=example,dc=com`).
  - `ou` (*organizational unit*): Abteilungen/Container (`ou=people`, `ou=developers`).
  - `cn` (*common name*) / `uid` (*user id*): Einzelobjekt. Zusammen ergibt sich der eindeutige Pfad **Distinguished Name (DN)**, z. B. `uid=sascha,ou=developers,ou=people,dc=example,dc=com`.
- **LDIF & Tools:** Einträge werden im Textformat **LDIF** gepflegt und per `ldapadd`, `ldapmodify` und `ldapsearch` verwaltet (Schema-Klassen z. B. `person`, `inetOrgPerson`, `posixAccount`).
- **Linux-Login via PAM:** `/etc/nsswitch.conf` (`passwd: files ldap` – `files` immer behalten, damit `root` lokal bleibt!) und `/etc/pam.d/login` (`pam_ldap.so`).
