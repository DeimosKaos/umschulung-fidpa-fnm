## 📖 Schritt 2: Einmaliges Lesen *(Fokus-Wissen aus Kersken)*

### 1. Teststufen & Testverfahren *(Kersken 11.1.4)*

| Teststufe | Was wird getestet? | Wer testet? |
| :--- | :--- | :--- |
| **1. Unit-Test *(Modultest)*** | Einzelne Funktion / Methode isoliert | Entwickler *(automatisiert)* |
| **2. Integrationstest** | Zusammenspiel mehrerer Module / DB / REST-API | Entwickler / CI-Pipeline |
| **3. Systemtest** | Gesamtsystem gegen alle Anforderungen (inkl. Performance) | QA / Entwickler |
| **4. Abnahmetest *(UAT)*** | Praxistauglichkeit gegen Lasten-/Pflichtenheft | **Kunde / Fachbereich** |

* **Black-Box-Test:** Testet von außen ohne Blick in den Code (*Äquivalenzklassen* & *Grenzwertanalyse*, z. B. `0`, `1`, `100`, `101`).
* **White-Box-Test:** Testet innere Verzweigungen/Pfade mit Code-Kenntnis (*Zweig-/Anweisungsüberdeckung*).

---

### 2. Unit-Tests & TDD: Red–Green–Refactor *(Kersken 11.2.3)*

* **Unit-Test-Aufbau:** *Arrange* (Testdaten vorbereiten) → *Act* (Funktion aufrufen) → *Assert* (`assertEquals`, `assertRaises`).
* **TDD *(Test-driven Development)*:**
  1. **Red:** Zuerst einen Test schreiben, der fehlschlägt *(Feature existiert noch nicht)*.
  2. **Green:** Minimalen Code schreiben, bis der Test grün ist.
  3. **Refactor:** Code aufräumen/optimieren, während alle Tests grün bleiben.
* **ML-Validierung:** Zusätzlich zu Code-Unit-Tests prüft **Cross-Validation** ($k$-Fold) die Stabilität der Modellmetriken (Precision/Recall/F1, RMSE).

## 🔺 Schritt 3: N – Nuklei & Pyramidenschema®

![[../../assets/LF12.08_Pyramide.svg]]

- **Spitze:** Mehrstufige Tests (Unit bis UAT), TDD (Red-Green-Refactor) und Cross-Validation liefern den objektiven Qualitätsnachweis im Projekt.
- **Nukleus 1 (Testpyramide & Arten):** Unit → Integration → System → Abnahmetest (UAT durch Kunde) Black-Box: Äquivalenzklassen & Grenzwerte White-Box: Codepfade & Überdeckung (Coverage)
- **Nukleus 2 (Unit-Tests & TDD (11.2.3)):** Arrange – Act – Assert TDD-Zyklus: 1. Red (Test schlägt fehl) 2. Green (minimal lösen) 3. Refactor (Code verbessern)
- **Nukleus 3 (ML- & Daten-Tests):** Schema- & Null-Tests für ETL k-Fold Cross-Validation gegen zufällige Train/Test-Splits Testprotokoll mit Datum & Ergebnis für IHK-Doku!
