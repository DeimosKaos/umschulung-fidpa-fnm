## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. JavaScript & DOM-Manipulation (Kersken 20.1–20.2)
**JavaScript** läuft (anders als PHP!) **direkt im Browser des Clients**. Um die geladene HTML-Seite nachträglich zu verändern, greift JS auf das **DOM (*Document Object Model*)** zu – die Baumstruktur aller HTML-Knoten im Arbeitsspeicher:
- Elemente finden: `document.getElementById("status")` oder `document.querySelector(".card")`.
- Inhalte & Events ändern: `el.textContent = "OK";` und `btn.addEventListener("click", () => { ... });`.
- **Sicherheitsregel:** Clientseitige JS-Formularprüfung ist nur Komfort – ein Angreifer kann JS abschalten oder die API direkt per `curl` aufrufen! Das Backend muss *immer* selbst validieren.

> [!question] ⏸️ Denkstopp (10 Sek.)
> *Warum nutzt man im Browser besser `el.textContent` statt `el.innerHTML`, wenn Daten von einer externen API oder einem Nutzer kommen?*

### 2. Asynchrones Laden: Ajax & `fetch()` (Kersken 20.3)
Klassische Webseiten laden bei jedem Klick das komplette HTML neu. **Ajax** (*Asynchronous JavaScript and XML*) sendet HTTP-Requests **asynchron im Hintergrund** an eine REST-API (meist mit **JSON** statt XML) und aktualisiert nur den betroffenen DOM-Teil:
- **Klassisch (Kersken 20.3):** `XMLHttpRequest` mit Callback `onreadystatechange` (`readyState === 4 && status === 200`).
- **Modern (Promises / `async-await`):**
  ```javascript
  const res = await fetch("/api/language/3", { headers: { Accept: "application/json" } });
  const data = await res.json(); // parst JSON direkt in ein JS-Objekt
  ```
- **CORS-Hinweis:** Browser blockieren Ajax-Anfragen an fremde Domains standardmäßig (*Same-Origin Policy*), sofern der Server keine `CORS`-Header erlaubt.

> [!question] ⏸️ Denkstopp (10 Sek.)
> *Was bedeutet das „Asynchron“ in Ajax – warum friert die Webseite während eines langsamen API-Aufrufs nicht ein?*

### 3. Moderne UIs mit React.js (Kersken 20.4)
Bei komplexen Dashboards wird manuelles `document.querySelector()` unübersichtlich. **React.js** zerlegt die Oberfläche in wiederverwendbare **Komponenten** (mit **JSX** und eigenem **State**). Ändern sich API-Daten im State, berechnet React im **Virtual DOM** nur die minimal nötigen Änderungen und aktualisiert das echte DOM blitzschnell.
