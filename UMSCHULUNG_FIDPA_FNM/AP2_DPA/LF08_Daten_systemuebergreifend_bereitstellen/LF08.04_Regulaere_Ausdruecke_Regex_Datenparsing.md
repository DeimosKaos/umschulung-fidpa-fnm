## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Regex-Syntax: Anker, Klassen & Quantoren (Kersken 9.1)
Ein **Regulärer Ausdruck (*RegExp*)** beschreibt ein formales Suchmuster für Zeichenketten:

| Element | Bedeutung | Beispiel |
| :--- | :--- | :--- |
| `^` / `$` | **Anfang** bzw. **Ende** des Strings/Zeile (`re.M`) | `^\d{5}$` (exakt 5-stellige PLZ!) |
| `.` | Ein beliebiges Zeichen (außer `\n`) | `a.c` trifft `abc`, `a-c` |
| `\d`, `\w`, `\s` | Ziffer `[0-9]`, Wortzeichen, Whitespace (`\D`, `\W`, `\S` negiert) | `\s*` (beliebig viel Leerraum) |
| `[...]` / `[^...]` | Zeichenauswahl / negierte Auswahl | `[^0-9]` (keine Ziffer) |
| `?`, `*`, `+`, `{n,m}` | `0–1`, `0–∞`, `1–∞`, `n` bis `m` Wiederholungen | `\-?\d+(\.\d+)?` (Zahl opt. mit `-` und `.`) |
| `(...)` | **Capture Group** für Teil-Extraktion | `(\d{5})\s+([A-ZÄÖÜa-zäöüß-]+)` |

> [!question] ⏸️ Denkstopp (10 Sek.)
> *Warum reicht das Muster `\d{5}` bei einer PLZ-Prüfung **nicht** aus, und was ändern die Anker `^\d{5}$`?*

### 2. Python (`re`) vs. Java (`Pattern` / `Matcher`) (Kersken 9.1)
- **Python (`import re`):** `p = re.compile(muster, flags)` (`re.I` ignoriert Groß/Klein, `re.M` mehrzeilig).
  - `match()` prüft ab String-Anfang, `search()` sucht überall, `findall()` liefert alle Treffer als Liste.
  - `sub("\\2, \\1", text)` ersetzt mit **Backreferences** (oder einer `lambda match:`-Funktion!); `split()` zerlegt Strings.
- **Java (`java.util.regex`):** `Pattern p = Pattern.compile("..."); Matcher m = p.matcher(txt);` (Backslash in Java-Strings doppelt escapen: `\\d`!). Schleife mit `while (m.find()) { m.group(1); }`. Ersetzen mit `$1, $2` in `replaceAll()`.

> [!question] ⏸️ Denkstopp (10 Sek.)
> *Warum zerlegt `"Wörter".split("\\W+")` in Java das Wort am `ö` falsch, und wie löst man das laut Kersken sauber?*

### 3. Grenzen & Praxis-Fallen (Kersken 9.1)
- **Umlaut-Falle (`\W`):** In Java deckt `\w` nur ASCII-Zeichen ab – `ä, ö, ü, ß` gelten dort als Nicht-Wortzeichen (`\W`)! Lösung: Unicode-Klasse **`\p{L}`** für alle Buchstaben.
- **Nicht übertreiben:** Komplexe verschachtelte Formate (HTML, XML, JSON) parst man **nie** mit Regex, sondern mit dedizierten Parsern (`xml.etree`, `json.load`)!
