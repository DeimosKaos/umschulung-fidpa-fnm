## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. REST-Prinzip & CRUD-Mapping (Kersken 19.2)
**REST (*REpresentational State Transfer*)** nutzt konsequent die Standard-Methoden von HTTP, um **Ressourcen** (Substantive in der URL, z. B. `/language/`, *nicht* Verben wie `/getLanguage`!) zu verwalten:

| CRUD | HTTP-Methode | URL-Beispiel (`19.2.1`) | Bedeutung & Body |
| :--- | :--- | :--- | :--- |
| **Read** | `GET` | `/language/` oder `/language/3` | Liste oder Einzelressource lesen (kein Body) |
| **Create** | `POST` | `/language/` | Neue Ressource anlegen (Daten im Body) → oft `201 Created` |
| **Update** | `PUT` *(oder `PATCH`)* | `/language/3` | Vorhandene Ressource ersetzen/ändern (Daten im Body) |
| **Delete** | `DELETE` | `/language/25` | Ressource mit ID `25` löschen |

> *Warum ist der Endpunkt `POST /api/deleteCustomer?id=5` schlechtes REST-Design – wie lautet er REST-konform?*

### 2. JSON vs. XML, Header & Statuscodes (Kersken 19.2.1)
- **Formate:** Typisch **JSON** (`application/json`, heute Standard) oder **XML** (`application/xml`).
  - **`Accept: application/json`** (Client → Server): *„Ich möchte die Antwort als JSON!“*
  - **`Content-Type: application/json`** (Client → Server bei `POST`/`PUT`): *„Mein Request-Body ist JSON!“*
- **Saubere Statuscodes:** `200 OK`, `201 Created`, `400 Bad Request` (ungültige Eingabe), `401 Unauthorized` (Auth fehlt), `404 Not Found` (ID existiert nicht), `501 Not Implemented` (Methode nicht unterstützt).

### 3. Architektur, Sicherheit & Testen (`19.2.2`)
- **Schichtenarchitektur:** Front-Controller (`index.php` via `.htaccess`) → Router (`Application`) → Ressourcen-Klasse (`Language` erbt von `Api`) → Datenzugriff (`Dba` trennt DB-Spaltennamen von API-Feldnamen) → `Response` (JSON/XML).
- **Auth:** Einfache API-Keys nie im Klartext speichern (Hash!). Produktivstandard ist **OAuth2 / Bearer-Token (JWT)** über **HTTPS**.
- **Testen:** Automatisierte API-Tests und manuelle Checks mit `curl`, **Postman / Insomnia** oder Python `requests`.
