## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Container-Virtualisierung mit Docker (Kersken 14.4.3)
Während eine VM komplette Hardware emuliert und ein eigenes Gast-OS bootet, teilen sich **Container** auf Linux den **Kernel des Host-Betriebssystems** (auf Windows/macOS läuft dafür eine kleine Linux-VM). Eine historische Vorstufe war `chroot` (nur Dateisystem-Isolation); Docker isoliert zusätzlich Prozesse und Netzwerk:
- **Vorteil:** Extrem geringer RAM-/CPU-Bedarf, Sekundenschneller Start, identische Umgebung von Entwicklung (CI/CD mit Jenkins) bis Produktion.
- **Nachteil:** Man kann kein beliebiges anderes OS-Kernel-System im Container booten (Linux-Container braucht Linux-Kernel).

**Zentrale Docker-Praxis:**
- `docker run -d --name db -p 3307:3306 -v ~/data:/var/lib/mysql --restart unless-stopped mysql:8.0`
  - `-d`: Im Hintergrund (*detach*).
  - `-p Host:Container`: Port-Mapping (`3307` auf Host → `3306` im Container).
  - `-v Hostpfad:Containerpfad`: **Persistentes Volume** – ohne `-v` gehen Datenbankdaten beim Löschen des Containers verloren!
  - `--restart`: `no`, `on-failure`, `always`, **`unless-stopped`** (für Produktion empfohlen).
- `docker ps` (laufende Container), `docker exec -it <ID> /bin/bash` (Shell im Container), **`Dockerfile`** (Bauplan). Für viele Container im Cluster nutzt man Orchestrierung wie **Kubernetes**.

### 2. Cloud Computing: IaaS, PaaS, SaaS (Kersken 14.4.4)
Cloud Computing bedeutet das dynamische Mieten von IT-Ressourcen (oft stündlich/nutzungsabhängig), gesteuert über **REST-APIs / SDKs** (z. B. AWS, Microsoft Azure):
1. **IaaS (*Infrastructure as a Service*):** Gemietete virtualisierte Hardware (VMs, Storage, Netz – z. B. AWS EC2, Azure VMs; Sonderform *Bare Metal Cloud* für dedizierte Server). Du verwaltest OS, Patches und Apps selbst.
2. **PaaS (*Platform as a Service*):** Gemietete Laufzeitplattformen/Serverdienste (z. B. gemanagte Datenbanken, App-Plattformen). Du verwaltest nur deine Anwendung/Daten.
3. **SaaS (*Software as a Service*):** Fertige, sofort nutzbare Software im Browser (z. B. Microsoft 365, CRM). Kein eigener Installations-/Wartungsaufwand.

> **Kerskens Cloud-Warnung:** Cloud-Provider garantieren zwar hohe Uptime (99–100 %), aber **Backups** bleiben nötig, Daten liegen auf Storage-Servern oft unverschlüsselt (**selbst verschlüsseln!**), und bei US-Anbietern greift die **DSGVO** (EU-Rechenzentren wählen!).
