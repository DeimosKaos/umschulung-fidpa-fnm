## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Der Kernel: Die Grenze zwischen User Mode und Kernel Mode
Ein **Betriebssystem (OS)** – etwa **Windows** oder **Linux** (Kernel von Linus Torvalds 1991 + GNU-Werkzeuge) – bildet die Brücke zwischen Hardware und Benutzer. Sein Herzstück ist der **Kernel**: das einzige Programm, das direkt nach dem Booten permanent auf der CPU läuft und über **Treiber** mit der Hardware spricht.

Um Stabilität zu garantieren, trennt die CPU zwei Sicherheitszonen:
- **Kernel Mode (privilegiert):** Hier läuft nur der Kernel mit vollem Hardware-Zugriff.
- **User Mode (eingeschränkt):** Hier laufen alle normalen Apps (Browser, Python, Excel). Will eine App eine Datei öffnen oder Netzwerk senden, muss sie den Kernel höflich über einen **System Call** bitten. Stürzt eine App ab, bleibt das restliche System stabil!

*(Bei der Kernel-Bauweise unterscheidet man **monolithische Kernels** wie Linux – alle Kernfunktionen im Kernel, sehr schnell – und **Mikrokernels**, die nur das Nötigste im Kernel lassen und Treiber in den User Mode auslagern, was sicherer ist, aber durch ständige Moduswechsel Zeit kostet.)*

### 2. Prozessverwaltung: Prozesse, Threads & Scheduling
Ein Programm auf der Festplatte ist nur toter Code. Sobald du es startest, wird daraus ein **Prozess** – ein laufendes Programm mit **eigenem, isoliertem Speicherbereich**. Da Prozesse recht schwerfällig sind, lassen sie sich intern in leichtgewichtige **Threads** unterteilen, die sich denselben Speicher ihres Prozesses teilen und dadurch schneller kommunizieren.

Damit 100 Prozesse gleichzeitig auf z. B. 8 CPU-Kernen laufen können, verteilt der **Scheduler** blitzschnell kurze Zeitscheiben (**Time-Slices**, *preemptives Multitasking*). Jeder Prozess durchläuft dabei drei Grundzustände:
- **Running:** rechnet gerade aktiv auf der CPU.
- **Ready:** wartet in der Schlange auf die nächste freie CPU-Zeitscheibe.
- **Blocked / Waiting:** wartet auf ein langsames Ereignis (z. B. Festplatte oder Netzwerkpaket) und gibt die CPU freiwillig ab.

### 3. Speicherverwaltung: Virtueller Speicher, Paging & Swapping
Kein Programm weiß vorher, wo im physischen RAM gerade Platz ist. Deshalb gibt das Betriebssystem jedem Prozess einen eigenen, scheinbar durchgehenden **virtuellen Speicherraum**. Die **MMU (*Memory Management Unit*)** übersetzt diese virtuellen Adressen blitzschnell in echte physische RAM-Adressen.

Technisch wird der Speicher dafür in gleich große Häppchen zerlegt (**Paging**): virtuelle **Pages** passen exakt in physische **Frames** im RAM. Wird der physische RAM knapp, lagert das OS momentan ungenutzte Pages auf die Festplatte/SSD aus (**Swapping** in die `Auslagerungsdatei` bzw. Linux-`Swap`-Partition). Das verhindert Abstürze – wird aber zu viel geswappt (*Thrashing*), bricht die Systemleistung massiv ein!

### 4. Dateisysteme: Ordnung & Schutz vor Datenverlust
Ohne **Dateisystem** wäre eine SSD nur ein riesiges Meer aus unbenannten Blöcken. Das Dateisystem organisiert diese Blöcke in eine **Ordnerstruktur** und verwaltet **Metadaten** (Dateiname, Größe, Zeitstempel, Besitzer, Zugriffsrechte und Block-Zeiger – unter Linux in **Inodes**, unter Windows NTFS in der **MFT** *Master File Table*).

Moderne Dateisysteme wie **`ext4`** (Linux) oder **`NTFS`** (Windows) nutzen **Journaling**: Bevor eine Änderung endgültig auf die Platte geschrieben wird, notiert das System den geplanten Schritt in einem Protokoll (*Journal*). Fällt mitten beim Speichern der Strom aus, liest das OS beim Neustart das Journal und verhindert so eine Beschädigung der gesamten Ordnerstruktur.
