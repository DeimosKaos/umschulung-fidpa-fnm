## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Syntax, Einrückung und das Objektmodell hinter Variablen
Python wurde für maximale Lesbarkeit entworfen. Statt Codeblöcke wie in Java oder C mit geschweiften Klammern `{ ... }` abzugrenzen, nutzt Python konsequent **Einrückung** (Standard: **4 Leerzeichen**, niemals Tabs und Leerzeichen mischen!). Ein Doppelpunkt `:` leitet einen Block ein, und alle Zeilen auf derselben Einrückungsebene gehören zusammen. Kommentare beginnen mit `#`, mehrzeilige Dokustrings stehen in `""" ... """`.

Bei Variablen verfolgt Python zwei Prinzipien: **dynamische Typisierung** (Variablen brauchen vorab keinen deklarierten Typ; `type(x)` verrät jederzeit den aktuellen Objekttyp) und das **Referenzmodell**. Eine Variable ist keine Schachtel, sondern ein **Namensschild**, das auf ein Objekt im Speicher zeigt (prüfbar mit `id(x)`). Nach Konvention nutzt man `snake_case` für Variablen/Funktionen und `CamelCase` für Klassen.

Die wichtigsten eingebauten Basisdatentypen sind:
- `int` (Ganzzahlen mit **beliebiger Genauigkeit** – auch `0x` Hex, `0o` Oktal, `0b` Dual),
- `float` (64-Bit-Gleitkommazahlen), `complex` (komplexe Zahlen),
- `str` (unveränderliche UTF-8-Texte, auch mehrzeilig mit `"""`),
- `bool` (`True`, `False`) und `None` (leerer Platzhalter).

Entscheidend ist der Unterschied zwischen **immutable (unveränderlich)** und **mutable (veränderlich)**:
- **Immutable** sind `int`, `float`, `str` und `tuple`. Änderst du `x = x + 1`, entsteht ein *neues* Objekt mit neuer `id()`.
- **Mutable** sind `list`, `dict` und `set`. Sie lassen sich *am selben Speicherort* verändern. Wenn du `liste2 = liste1` schreibst, **kopierst du nicht**, sondern klebst nur ein zweites Namensschild auf dieselbe Liste! Jede Änderung an `liste2` verändert dann unbemerkt auch `liste1`.

### 2. Operatoren: Rechnen, Vergleichen, Short-Circuit und Identität
Python trennt sauber zwischen normaler Division `/` (liefert **immer** `float`, z. B. `6 / 2 == 3.0`), **ganzzahliger Division `//`** (`7 // 2 == 3`), **Modulo `%`** (Divisionsrest `7 % 2 == 1`) und **Potenz `**`** (`2 ** 3 == 8`). Auf Strings verbindet `+` Texte und `*` wiederholt sie (`"Ha" * 3 == "HaHaHa"`). Mit **Bit-Operatoren** (`&`, `|`, `^`, `<<`, `>>`, `~`) lassen sich speichersparend Bitflags prüfen und umschalten, und alle Rechenoperatoren können mit `=` kombiniert werden (`a += 6`).

Bei **Vergleichsoperatoren** (`<`, `>`, `<=`, `>=`, `==`, `!=`) konvertiert Python automatisch zwischen `int` und `float` (`42 == 42.0` ist `True`), aber **niemals** zwischen Zahl und String: `3 == "3"` ergibt `False`, und `3 < "3"` wirft sofort einen `TypeError`!

Die **logischen Operatoren** `and`, `or` und `not` arbeiten mit **Short-Circuit-Logik (Kurzschluss)**: Sobald das Ergebnis feststeht, bricht die Auswertung ab. Dabei werten Werte wie `0`, `""`, `[]`, `()` und `None` als *Falsy* (`False`), alles andere als *Truthy* (`True`) – und `and`/`or` geben direkt den entscheidenden Teilausdruck zurück! Zudem prüft `==` auf **Wertgleichheit**, während der Identitätsoperator **`is`** (Umkehrung `is not`) prüft, ob zwei Variablen auf **exakt dasselbe Objekt** im Speicher zeigen. Mit **`in`** (`not in`) testest du, ob ein Teilstring oder Element in einem Container vorkommt (bei Strings *case-sensitive*).

### 3. Sequenzen im Griff: Listen, Tupel und Mengen (`set`)
Für Sammlungen mehrerer Werte stellt Python drei zentrale Containertypen bereit:
- **Liste (`list`, `[...]`):** Eine geordnete, **veränderliche** Sammlung beliebiger Typen. Der Zugriff erfolgt 0-basiert (`liste[0]`) oder von hinten negativ (`liste[-1]` für das letzte Element). Mit dem **Slice-Operator** `liste[start:ende:schritt]` schneidest du Teilbereiche heraus – wichtig: der `ende`-Index ist **exklusiv**! Ein Slice erzeugt immer eine **flache Kopie**; `kopie = original[:]` löst somit das Alias-Problem bei Listen. Auch Zuweisungen an Slices (`liste[1:3] = []` zum Löschen) sind möglich.
- **Tupel (`tuple`, `(...)`):** Eine **unveränderliche** Sequenz (oft für feste Datensätze genutzt). Indizieren und Slicen funktionieren wie bei Listen, aber `tupel[1] = "neu"` löst einen `TypeError` aus. **Wichtige Syntax-Falle:** Ein Tupel mit nur *einem* Element braucht zwingend ein Komma: `(1,)` ist ein `tuple`, `(1)` nur ein `int`!
- **Menge (`set`):** Eine **ungeordnete** Sammlung **eindeutiger** Elemente ohne Index – ideal für schnelle Mitgliedschaftsprüfungen (`in`) sowie Schnitt-, Vereinigungs- und Teilmengenoperationen.
