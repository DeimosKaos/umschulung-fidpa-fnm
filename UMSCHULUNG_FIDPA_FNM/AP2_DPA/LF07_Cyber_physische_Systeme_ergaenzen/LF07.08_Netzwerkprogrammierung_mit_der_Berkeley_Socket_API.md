## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Die Berkeley Socket API (Kersken 9.3.1)
Die **Berkeley Socket API** (ursprünglich in C für BSD-Unix, unter Windows als *WinSock*, in Python im Modul `socket`) ist die universelle Schnittstelle für TCP/IP-Netzwerkprogramme. Anders als unidirektionale Pipes ist ein **Socket-Paar immer bidirektional** (gleichzeitig lesen und schreiben).

**Socket erzeugen (`socket.socket(domain, type, protocol)`):**
- `domain`: **`socket.AF_INET`** für TCP/IP-Netzwerke (`AF_UNIX` für lokale Unix-Domain-Sockets).
- `type`: **`socket.SOCK_STREAM`** für verbindungsorientiertes **TCP**; **`socket.SOCK_DGRAM`** für verbindungsloses **UDP**.
- Hilfsfunktionen: `socket.gethostbyname("example.com")` (DNS → IP) und `socket.getservbyname("http", "tcp")` (Dienst → Port).

### 2. TCP-Client vs. TCP-Server Ablauf (Kersken 9.3.1–9.3.2)
- **UDP (verbindungslos):** `sock.sendto(msg, (ip, port))` und `sock.bind(...)` + `sock.recvfrom(bufsize)`.
- **TCP-Client:**
  1. `sock.connect((ip, port))` (baut TCP-Verbindung auf).
  2. `sock.send(b"...")` (sendet **Bytes** `b"..."`, keinen Unicode-String!).
  3. `data = sock.recv(buffersize)` (empfängt bis zu `buffersize` Bytes).
- **TCP-Server (klassische Reihenfolge!):**
  1. `serversock.bind(("", 8000))` — Bindet Socket an lokale IP/Port. *(Achtung: Well-known Ports **< 1024** erfordern unter Unix `root`-Rechte!)*
  2. `serversock.listen(max_queue)` — Schaltet in den **Listening**-Modus (`socket.SOMAXCONN` für max. Warteschlange).
  3. `(clientsock, addr) = serversock.accept()` — Blockiert bis ein Client verbindet und liefert ein **neues Client-Socket** zurück. Für parallele Clients startet der Server dahinter z. B. `os.fork()` oder einen Thread (`9.3.2`)!
