## Schritt 2 – Einmaliges Lesen: Das Phänomen verstehen

### 1. Das Domain Name System (DNS – RFC 1034 / 1035)
Im frühen ARPANET reichte eine zentrale Textdatei (`hosts.txt`). Heute existiert sie noch lokal als `/etc/hosts` (Unix) bzw. `<Windows>\system32\drivers\etc\hosts` – findet ein Rechner den Namen dort (z. B. zum Blocken von Phishing-/Werbe-Domains), fragt er keinen Nameserver mehr. Für das gesamte Internet war eine zentrale Datei aber viel zu groß und zu träge.

Darum wurde **DNS** als **verteilte, hierarchische Datenbank** eingeführt (wichtigste Server-Software unter Unix: **BIND**):
- **Aufbau (umgekehrt zum Dateipfad!):** Bei `/home/sascha/datei.txt` steht das Allgemeinste links; bei `www.buecher.lingoworld.de` steht der **speziellste Host/Dienst links**, die **Top-Level-Domain (TLD)** rechts (ganz rechts liegt unsichtbar die leere **Root-Zone** der **ICANN**).
- **TLD-Typen:** **Generic TLDs** (`.com`, `.org`, `.net`, `.edu`, `.gov`, `.info`) vs. **Country TLDs / ccTLDs** (`.de`, `.uk`, `.ch`, teils branchenfremd genutzt wie `.tv` für Tuvalu). Manche Länder unterteilen weiter (`.co.uk`).
- **Zonen & Ausfallsicherheit:** Jede delegierte Ebene bildet eine unabhängige **Zone**. Aus Sicherheitsgründen braucht jede Domain mindestens zwei Nameserver in getrennten Netzen: einen **primären Master-Nameserver** und einen automatisch replizierenden **Slave-Nameserver**.
- **Ablauf einer Abfrage:** Browser kennt IP nicht → fragt Provider-Nameserver → der fragt notfalls den TLD-Nameserver (`.de`) → der verweist auf den autoritativen Nameserver der Domain (z. B. `google.de`) → Antwort wird zurückgegeben und im **Cache** zwischengespeichert.

### 2. Klartext-Protokolle: Telnet vs. SSH & FTP
Das Schöne an vielen Internetprotokollen: Sie sprechen englische Klartextbefehle und lassen sich sogar mit `telnet <Host> <Port>` testen!
- **Telnet (TCP 23) vs. SSH (TCP 22):** Beide bieten eine entfernte Terminal-Shell (auch für Vollbild-Editoren wie `vi`/`Emacs`). **Telnet überträgt alles inkl. Passwörtern im Klartext!** Deshalb nutzt man heute **SSH (Secure Shell)** (z. B. **OpenSSH**), das die gesamte Verbindung verschlüsselt. *(Hinweis: Grafische Unix-Programme auf einem entfernten Server brauchen lokal auf deinem Rechner einen **X-Window-Server**, weil der die Zeichen-Dienste anbietet!)*
- **FTP (TCP 20/21) & SFTP/FTPS:** Klassische Befehle sind `pwd`, `cd`, `ls`, `get` (Download), `put` (Upload) und `quit`.
  - **Kritische Falle – ASCII vs. Binary:** Unix nutzt `LF` (Byte 10) als Zeilenumbruch, Windows `CR+LF` (13+10), altes Mac OS `CR` (13). Im **`ascii`-Modus** wandelt FTP diese Bytes automatisch um – nützlich für Textdateien, aber **tödlich für Binärdateien** (Bilder, Musik, Programme), weil zufällige `10`-Bytes zerstört werden! Darum für alles außer reinem Text **`binary`** nutzen (bzw. moderne verschlüsselte Varianten **SFTP / FTPS**).

### 3. E-Mail: SMTP, MIME und POP3 vs. IMAP4
Hinter E-Mail stecken mindestens zwei Serverdienste:
1. **Versand mit SMTP (TCP 25, RFC 2821):** Der Client liefert die Mail mit Klartextbefehlen ab: `HELO` → `MAIL From:` → `RCPT To:` → `DATA` (Nachricht, beendet durch eine einzelne Zeile mit `.`) → `QUIT`. Gegen Spam/Missbrauch prüfen Server heute per **Username/Passwort** (früher teils nur IP-Prüfung oder *SMTP after POP*).
2. **Aufbau & Anhänge mit MIME (RFC 2045–2049):** Klassisches RFC-822-Format kennt nur Textheader (`From:`, `To:`, `Subject:`, `Cc:`, `Bcc:`). **MIME** ergänzt `Content-Type` (z. B. `text/plain`, `text/html`, `image/jpeg`, `multipart/mixed` für **Attachments**, `multipart/alternative` für Text + HTML gleichzeitig) und `Content-Transfer-Encoding`:
   - `7bit` / `8bit` (Text)
   - `quoted-printable` (Sonderzeichen hexadezimal mit `=`, z. B. `gr=FC=DFer`)
   - **`base64`** (verpackt **Binärdaten/Anhänge** 7-Bit-sicher für alte Mailserver).
3. **Abholung mit POP3 vs. IMAP4:**
   - **POP3 (TCP 110):** Befehle `USER`, `PASS`, `LIST`, `RETR <Nr>`, `DELE <Nr>`, `QUIT` – lädt Mails meist herunter und löscht sie vom Server.
   - **IMAP4 (Standardport TCP 143):** verwaltet Ordner **direkt auf dem Mailserver** – ideal für mobiles Arbeiten auf mehreren Geräten. *(Webmail wie GMX/Gmail ist eine Weboberfläche vor IMAP + SMTP.)*

### 4. Das World Wide Web (HTTP)
Im Web fordert der **Browser** über eine TCP-Verbindung per **HTTP** (HTTP 1.1 in RFC 2616) eine Dokumentadresse (**URL**) an, erhält das **HTML**-Dokument (plus CSS/JavaScript) und lädt eingebettete Bilder sowie über **Hyperlinks** verknüpfte Seiten nach.
