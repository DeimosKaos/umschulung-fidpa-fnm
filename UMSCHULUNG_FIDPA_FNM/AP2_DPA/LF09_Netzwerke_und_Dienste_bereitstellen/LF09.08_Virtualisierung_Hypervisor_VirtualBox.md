## Schritt 2: Einmaliges Lesen *(IHK-relevanter Text, phänomenologisch aufbereitet)*

### 1. Warum Virtualisierung? Host, Gast & Hypervisor (Kersken 14.4)
Einzelne Server nutzen CPU und RAM oft nur zu wenigen Prozent aus. **Virtualisierung** teilt einen physischen Rechner (**Host**) in mehrere abgeschottete **Virtuelle Maschinen (VMs)** mit eigenem **Gastbetriebssystem** (z. B. Linux-VM auf Windows-Host oder umgekehrt). Die Verwaltungssoftware heißt **Hypervisor**:
- **Typ-1-Hypervisor (*Bare-Metal*):** Läuft direkt auf der Hardware ohne vollwertiges Host-OS (z. B. **VMware ESXi**, **Xen** mit Domäne 0, **Microsoft Hyper-V**, KVM/Proxmox). Hohe Performance, Standard im Rechenzentrum.
- **Typ-2-Hypervisor (*Hosted*):** Läuft als Anwendung auf einem regulären Host-Betriebssystem (z. B. **Oracle VirtualBox**, **VMware Workstation**, **Parallels Desktop**). Ideal für Desktop, Tests und Entwicklung.

### 2. VirtualBox & VM-Praxis (Kersken 14.4.2)
- **Virtuelle Festplatten:** Liegen als Datei auf dem Host – gängige Formate sind **VDI** (VirtualBox), **VHD** (Microsoft) und **VMDK** (VMware).
  - *Dynamisch alloziiert:* Wächst erst mit tatsächlichen Daten (spart Platz).
  - *Feste Größe:* Belegt sofort den gesamten Platz, bietet aber etwas **bessere Performance**.
- **Guest Additions:** Treiberpaket im Gast-OS für bessere Grafik, **Shared Folders**, **Shared Clipboard** und Drag & Drop.
- **Herunterfahren:** *Save the machine state* (RAM einfrieren), *Send shutdown signal* (sauberes OS-Herunterfahren), *Power off* (hartes Ausschalten).
- **Snapshots (Sicherungspunkte):** Frieren Zustand von RAM und Disk vor einem riskanten Update ein, sodass man sekundenschnell zurückrollen kann. *(Achtung IHK-Falle: Ein Snapshot liegt auf demselben Host und ist **kein Backup**!)*
- **Vagrant:** Beschreibt VMs reproduzierbar per Code (*Vagrant-File*).*
