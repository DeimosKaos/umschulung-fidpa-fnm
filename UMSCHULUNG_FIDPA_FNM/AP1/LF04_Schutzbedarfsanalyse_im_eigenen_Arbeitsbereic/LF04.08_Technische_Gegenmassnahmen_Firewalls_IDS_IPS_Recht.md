## Schritt 2 – Einmaliges Lesen: Das Phänomen verstehen

### 1. Firewalls, Bastion-Host & DMZ
- **Paketfilter vs. Application Gateway:** Ein einzelner Host-Paketfilter (z. B. `iptables` im Linux-Kernel) reicht im Unternehmen nicht allein. Eine **Application Gateway Firewall** auf einem dedizierten **Bastion-Host** filtert den gesamten ein- und ausgehenden Traffic.
- **DMZ (*Demilitarisierte Zone*):** Ein vorgeschaltetes Puffer-Netz zwischen Internet und internem Firmennetz, eingerahmt von Paketfiltern und Application Gateway Firewalls. Öffentliche Server (Web-, Mail-, VPN-Server) stehen **in der DMZ**; das interne Firmennetz greift nur kontrolliert über **autorisierte Proxys** zu.

#### Worked Example: Linux `netfilter / iptables` verstehen
Im Linux-Kernel prüft `netfilter` (konfiguriert per `iptables` bzw. `ip6tables` für IPv6) IP-Pakete anhand von **5 Chains**:
- `INPUT` (eingehend für diesen Host), `OUTPUT` (ausgehend von diesem Host), `FORWARD` (durchgereichtes Routing), `PREROUTING` (direkt bei Empfang), `POSTROUTING` (direkt vor Versand).
Und **3 Tabellen**: `filter` (eigentliches Erlauben/Verbieten), `nat` (`SNAT`, `MASQUERADE`, `DNAT`) und `mangle` (Header ändern).
Die wichtigsten **Targets (`-j`)**: `ACCEPT` (durchlassen), **`DROP`** (still verwerfen), **`REJECT`** (verwerfen + Ablehnungsmeldung senden), `QUEUE`, `RETURN`.

Beispielregel: Alle TCP-Pakete aus einem bekannten Malware-Netz `196.12.21.0/24` ganz oben (`-I`) in `INPUT` still verwerfen:
```bash
iptables -t filter -I INPUT -p tcp -s 196.12.21.0/24 -j DROP
```

### 2. Intrusion Detection Systems (IDS)
Ein **IDS** schlägt Alarm, wenn Angriffe oder Manipulationen passieren:
- **Host-Überwachung (`tripwire`):** Meldet unerwünschte Änderungen an Systemdateien und Binaries (entlarvt nachträglich installierte **Rootkits**).
- **Network IDS (`Snort`):** Überwacht den Netzwerkverkehr auf verdächtige Muster.
- **Goldene Regel:** Ein IDS muss installiert werden, **bevor** der Rechner erstmals ans Netz geht – sonst könnte der „Sauber-Zustand“ schon manipuliert sein!

### 3. Abschottung (`chroot`, Container) & aktive Prüfung (`Nessus`)
- **`chroot`-Käfig:** Gaukelt einem Unix-Serverdienst vor, ein Unterverzeichnis sei `/`. Bietet zusätzlichen Schutz, ist aber nicht unknackbar; heute nutzt man oft **Container (Docker)** oder **VMs** zur Isolation (siehe [[../LF02_Arbeitsplaetze_nach_Kundenwunsch_ausstatten/LF02.09_Virtualisierung_VirtualBox_Container_Docker_Cloud|LF 2.09]]).
- **Schwachstellen-Scans (`Nessus`):** Admins prüfen ihr eigenes Netz mit Scannern auf offene Lücken. *(Rechtlicher Hinweis: **§ 202c StGB** stellt „Hackertools“ nur dann unter Strafe, wenn sie der Vorbereitung einer Straftat bzw. ausschließlich kriminellen Zwecken dienen.)*
- **Passwörter (Kersken):** Keine einzelnen Wörter (besser Anfangsbuchstaben eines sinnlosen Satzes + Zahlen/Sonderzeichen), Groß/Klein mischen, **niemals aufschreiben**, regelmäßig wechseln!
