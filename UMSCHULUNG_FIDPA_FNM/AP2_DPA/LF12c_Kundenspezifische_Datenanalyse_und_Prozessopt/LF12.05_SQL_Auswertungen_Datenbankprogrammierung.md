## 📖 Schritt 2: Einmaliges Lesen *(Fokus-Wissen aus Kersken)*

### 1. Analytisches SQL für Datenauswertungen *(Kersken 13.3)*

| SQL-Klausel / Konstrukt | Funktion | Klassische IHK-Falle |
| :--- | :--- | :--- |
| **`INNER JOIN` vs. `LEFT JOIN`** | `INNER`: nur Treffer in beiden Tabellen. `LEFT`: **alle** Zeilen der linken Tabelle (auch ohne Umsatz/Treffer → `NULL` rechts!) | Wer nach *„Kunden ohne Bestellung“* sucht, braucht `LEFT JOIN ... WHERE bestellung_id IS NULL`! |
| **`WHERE` vs. `HAVING`** | `WHERE` filtert **einzelne Zeilen vor** `GROUP BY`; `HAVING` filtert **aggregierte Gruppen nach** `GROUP BY` | Aggregatfunktionen (`SUM`, `COUNT`, `AVG`) dürfen **nie** im `WHERE` stehen! |
| **Aggregatfunktionen** | `COUNT(*)`, `COUNT(spalte)` *(ohne NULL)*, `SUM()`, `AVG()`, `MIN()`, `MAX()` | `COUNT(*)` zählt auch Zeilen mit `NULL`-Werten in Einzelspalten |
| **CTEs (`WITH ... AS`) & Views** | Lesbare Zwischenabfragen oder gespeicherte virtuelle Sichten für wiederkehrende KPIs | Strukturieren komplexe Auswertungen sauber |

conn = sqlite3.connect("analytics.db")

## 🔺 Schritt 3: N – Nuklei & Pyramidenschema®

![[../../assets/LF12.05_Pyramide.svg]]

- **Spitze:** Analytisches SQL (JOINs, GROUP BY/HAVING) verdichtet Massendaten direkt auf dem Server, und Prepared Statements schützen Python-Abfragen vor SQL-Injection.
- **Nukleus 1 (JOINs & NULL-Logik):** INNER JOIN: Schnittmenge LEFT JOIN: alle links + NULL Unbedingt IS NULL statt = NULL! 'Kunden ohne Auftrag' → LEFT JOIN + WHERE b.id IS NULL
- **Nukleus 2 (Aggregation & HAVING):** Reihenfolge: FROM → WHERE → GROUP BY → HAVING → SELECT WHERE filtert Zeilen vorab HAVING filtert Gruppen danach (z. B. HAVING COUNT(*) > 5)
- **Nukleus 3 (Python & Security (13.5)):** DB-API: connect → cursor → execute → fetchall → close Prepared Statements (?, %s) verhindern SQL-Injection! Nie f-Strings für SQL-Werte!

> [!tip] 💡 IHK-Prüfungstipp
> Merke die SQL-Ausführungsreihenfolge: `FROM/JOIN` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` → `LIMIT`. Deshalb funktioniert `WHERE SUM(x) > 100` niemals!
