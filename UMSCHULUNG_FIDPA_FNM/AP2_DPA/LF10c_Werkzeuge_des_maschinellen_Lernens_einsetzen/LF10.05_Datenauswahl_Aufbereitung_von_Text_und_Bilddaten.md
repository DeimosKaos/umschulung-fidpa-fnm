## 📖 Schritt 2: Einmaliges Lesen *(Fokus-Wissen aus Kersken)*

### 1. Textdaten aufbereiten *(Kersken 10.2.1)*

ML-Algorithmen verarbeiten nur **Zahlen**, keine rohen Zeichenketten. Texte werden daher über das **Bag-of-Words-Modell** in eine numerische Feature-Matrix (*Dokument × Wort-Vokabular*) umgewandelt.

| Werkzeug / Parameter | Funktion & Wirkung | Wann einsetzen? |
| :--- | :--- | :--- |
| **`CountVectorizer`** (`sklearn`) | Zählt Wortvorkommen pro Text und erzeugt eine **Sparse Matrix** *(nur Werte ≠ 0 gespeichert)* | Standard für kleine bis mittlere Korpora; Vokabular bleibt lesbar (`get_feature_names_out()`) |
| **`stop_words`** | Filtert häufige, bedeutungsarme Füllwörter (*„der, die, und“*) heraus | Reduziert Rauschen und Feature-Anzahl |
| **`min_df` / `max_df`** | Ignoriert Wörter, die zu selten (`min_df`) oder in fast jedem Dokument (`max_df`) vorkommen | Entfernt Tippfehler & Allerweltswörter |
| **`ngram_range=(1, 2)`** | Erfasst neben Einzelwörtern *(Unigramme)* auch Wortpaare *(Bigramme, z. B. „nicht gut“)* | Wenn Wortreihenfolge/Negation Bedeutung trägt |
| **`HashingVectorizer`** | Hasht Wörter direkt auf eine **feste Anzahl** Features (`n_features=15`) | Sehr große Textmengen / Streaming; spart RAM, aber mögliche **Hash-Kollisionen** |

> [!question] ⏸️ Denkstopp (10 Sek.)
> Warum speichert `CountVectorizer` das Ergebnis als **Sparse Matrix** (*Compressed Sparse Row*) statt als normales vollbesetztes 2D-Array – und was würde sonst bei 100.000 Dokumenten und 50.000 Vokabeln im RAM passieren?

### 2. Bilddaten vorbereiten *(Kersken 10.2.2)*

Ein Farbbild mit nur `100 × 100` Pixeln hat bereits `10.000` Pixel × `3` Kanäle (RGB, je `0–255` = `16,7 Mio.` Farben) = `30.000` Features pro Bild! Für klassisches ML muss diese Datenflut reduziert werden:

```python
from skimage.io import imread, imshow
from skimage.transform import resize

image = imread("flower.jpg", as_gray=True)   # 1. Graustufen (2D-Array, Werte 0.0 bis 1.0!)
cropped = image[350:550, 250:450]            # 2. Relevanter quadratischer Ausschnitt (NumPy-Slicing)
resized = resize(cropped, (30, 30))          # 3. Verkleinerung auf einheitliche 900 Features
```

| Schritt | Effekt auf das NumPy-Array | Warum ML-relevant? |
| :--- | :--- | :--- |
| **`as_gray=True`** | Aus 3D `(H, B, 3)` wird 2D `(H, B)` mit **Floats in `[0.0, 1.0]`** | Reduziert Kanäle um 2/3 und übernimmt sofort die **Feature-Skalierung** |
| **Cropping (`[y1:y2, x1:x2]`)** | Schneidet störenden Hintergrund weg; gleiches Seitenverhältnis (z. B. Quadrat) | Alle Bilder müssen dieselben Proportionen & Fokus haben |
| **`resize(img, (N, N))`** | Einheitliche Zielgröße (z. B. `30×30 = 900` Features) | ML-Modelle erwarten **konstante Feature-Anzahl** pro Input |

> [!question] ⏸️ Denkstopp (10 Sek.)
> Wenn du Bilder auf `5×5` Pixel verkleinerst, hat das Modell zwar nur noch 25 Features – warum sinkt die Erkennungsrate trotzdem dramatisch?

## 🔺 Schritt 3: N – Nuklei & Pyramidenschema®

![[../../assets/LF10.05_Pyramide.svg]]

- **Spitze:** Texte und Bilder müssen vor dem Training durch Vektorisierung, Filterung und Dimensionsreduktion in kompakte Zahlen-Arrays überführt werden.
- **Nukleus 1 (Text → Bag of Words):** CountVectorizer: Wortzählung als Sparse Matrix (RAM-sparend) Tuning: stop_words, min_df, max_df, ngram_range HashingVectorizer: feste n_features (evtl. Kollisionen)
- **Nukleus 2 (Bilddaten reduzieren):** Rohbild: RGB (0..255) = zu viele Werte & 3D-Array (H, B, 3) as_gray=True → 2D-Array mit Floats 0.0..1.0 (skaliert!) Cropping: NumPy-Slicing resize(): einheitliche Größe
- **Nukleus 3 (Praxis-Abwägung):** Zu viele Features → langsam & Overfitting-Gefahr Zu starkes Verkleinern → Informationsverlust! Jupyter Notebooks (%matplotlib inline) ideal für EDA/Bilder

> [!tip] 💡 IHK-Prüfungstipp
> Merke bei `skimage.io.imread`: Mit `as_gray=True` liegen Pixel automatisch als Float zwischen `0.0` und `1.0` vor (Feature-Skalierung inklusive), bei Farbbildern (`as_gray=False`) als 3D-Integer-Array `0..255`.
